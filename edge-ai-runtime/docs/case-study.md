# Edge AI Pipeline 검증 Case Study

## 시작한 이유

보드에서 AI application이 실행되고 화면이 출력되는 것만으로는 어느 구간이 정상인지 판단하기 어려웠습니다. 저는 pipeline을 한 번에 평가하는 대신 inference 실행 시간, process 자원, kernel 메시지와 온도를 서로 다른 관측값으로 나눴습니다.

## 역할 구분

교육 환경은 평가 보드, 카메라, AI 모델, NPU runtime과 예제 application을 제공했습니다. 저는 측정 지점을 추가하고 반복 실행 절차, 로그 분석기, 조건별 비교표와 판정 기준을 구성했습니다.

공개 저장소의 Python 코드는 당시 분석 방법을 일반 이벤트 형식으로 다시 작성한 것입니다. 업체 소스와 SDK 구조를 재현하지 않습니다.

## 기준 측정

120초 실행에서 3577회의 inference 완료를 관측했습니다. 처음 10회를 warm-up에서 제외한 execute 평균은 3.074 ms, P99는 3.306 ms였고 완료 간격 기준 FPS는 약 30이었습니다. Process CPU 평균은 22.49%, 최대 RSS는 78.77 MiB였습니다.

Application은 정상 종료했지만 신규 page fault 메시지 12개와 GPU fault 메시지 30개가 관측됐습니다. 이 숫자는 독립 사고 횟수가 아니라 제한된 시험 구간에서 일치한 kernel log 행의 개수입니다. 화면 출력과 종료 코드만으로 해당 실행의 상태를 판단하지 않았으며, 제품 전체의 결함 건수로 해석하지 않습니다.

## GPU 오류 조건 분리

카메라 입력, inference와 후처리는 유지하고 화면에 그리는 요소를 나눠 짧게 반복했습니다. Texture만 표시하거나 texture와 검출 박스만 표시한 조건에서는 오류가 재현되지 않았습니다. Text rendering이 포함된 조건에서는 GPU 오류가 다시 나타났습니다.

이 결과는 해당 시험 환경에서 text rendering 경로를 우선 조사할 근거를 제공하지만, 짧은 무오류 실행이 영구적인 정상 동작을 뜻하지는 않습니다. 화면 내용도 완전히 통제한 입력이 아니므로 조건별 메시지 수를 개선율이나 제품 품질 지표로 비교하지 않았습니다.

Vertex buffer 변경 후보도 두 번째 실행과 결합 조건에서 오류가 다시 발생했습니다. 따라서 vertex 데이터 수명 하나만을 근본 원인으로 확정하지 않았습니다.

## 온도값 검토

추가 부하 없이 약 55초 동안 측정한 값은 영역별 평균 44.668도에서 46.709도 사이였고 작은 범위에서 변했습니다.

Pipeline 동시 수집에서는 100개 표본 중 93개가 31.609도로 같았습니다. 숫자를 정상적으로 읽었다는 사실만 확인했으며 실제 온도라고 판정하지 않았습니다. 실행 로그를 다시 확인한 결과 이 측정의 workload도 기준 측정과 다른 multi-task 모델이어서 성능 비교에서 제외했습니다.

이 자료로 냉각 성능이나 온도와 GPU 오류의 인과관계를 판단하지 않습니다.

## 배운 점

정상 화면, 정상 종료 코드와 정상 kernel 상태는 서로 다른 질문입니다. 또한 측정 도구가 값을 출력해도 정의와 수집 조건을 확인하지 않으면 잘못된 결론을 만들 수 있습니다. 이번 프로젝트에서는 관측층을 나누고, 가설을 좁혀도 확인하지 못한 부분을 그대로 남기는 방식을 익혔습니다.
