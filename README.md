# Embedded System Validation Projects

팹리스 일경험 교육에서 수행한 임베디드 시스템 검증 과정을 개인 포트폴리오 형태로 정리한 저장소입니다.

실험 조건을 통제하고, 로그와 측정값으로 확인 가능한 범위를 판단한 과정을 기록합니다.

## Projects

| 프로젝트 | 확인한 내용 | 개인 작업 범위 |
|---|---|---|
| [3보드 통신 검증](embedded-communication/) | heartbeat 장애와 복구, 상태 전이, DRIVER 이벤트 전달 및 중복 처리 | 검증 시나리오 설계, Python 검증 도구, 로그 수집과 결과 판정 |
| [Edge AI Runtime 검증](edge-ai-runtime/) | AI pipeline 기준 성능, GPU 오류 조건 분리, 온도 측정값 해석 | 측정 도구 작성, 반복 실험, 로그 분석과 가설 범위 축소 |

## Validation Approach

각 프로젝트는 다음 순서로 정리합니다.

1. 관찰한 현상과 검증 질문 정의
2. 가능한 원인과 확인 조건 정리
3. 실험 수행 및 원본 evidence 수집
4. 측정값과 상태 전이 분석
5. 확인한 사실과 확인하지 못한 범위 분리

## Disclosure

이 저장소는 교육 환경에서 수행한 개인 학습 및 검증 프로젝트를 설명합니다. 플랫폼 및 업체 식별 정보는 공개용으로 일반화했으며, 해당 기업이나 교육기관의 공식 검증 결과가 아닙니다.

업체 제공 소스 코드, SDK, 매뉴얼, 실행 바이너리와 원본 시스템 로그는 포함하지 않습니다. 공개된 코드는 개인이 작성한 검증 도구이거나 공개용으로 다시 구성한 예제입니다.

기재된 측정값은 제한된 교육용 보드와 시험 조건에서 얻은 관측 결과입니다. 특정 제품 전체의 성능, 품질 또는 결함을 판정하는 자료로 사용할 수 없습니다.

각 프로젝트 디렉터리에서 상세 case study, 공개용 분석 코드, 단위 테스트와 익명화한 집계 결과를 확인할 수 있습니다.
